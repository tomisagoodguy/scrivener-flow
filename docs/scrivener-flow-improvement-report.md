## 一、執業現場的核心痛點（為何改進）

代書的日常並非單線作業。一個案件從**簽約到交屋**平均歷時 30～90 天，期間要同時應付：

- 買賣雙方的各自要求（常常互相矛盾）
- 銀行催件、地政機關的窗口限制
- 稅務申報的死線（超期即罰款或喪失優惠）
- 仲介的頻繁詢問

「記憶體不足」是執業代書最大的作業風險。現有系統已有良好基礎，但仍有幾個關鍵痛點尚待解決。

### 從實際代書網站補充的現場事實

爬取台灣多個地政士事務所網站後，確認以下幾點與系統設計直接相關：

**流程時間現實**
- 完整簽約→交屋流程：**2～6 週**（至多一個半月），比原先認知更緊湊
- 用印到完稅：**7～14 天內**完成，不是一個月可以拖
- 銀行對保到核貸：**2～3 週**，這段時間案件處於「等待」狀態，系統需要清楚標示

**代償的二撥問題（系統完全沒有追蹤）**
實務上撥款分兩段進行（稱「二撥」）：
1. **第一撥**：買方銀行代位清償賣方舊貸款
2. **第二撥**：確認塗銷完成後，餘額才入專戶

若第一撥後塗銷尚未完成就進行第二撥，風險極大。目前系統只有一個 `redemption_date`，完全無法追蹤這個關鍵節點。

**代書的「奔波」問題（流程不只四步）**
網站資料顯示，一個案件實際要跑的機關：
- 地政事務所（謄本、申請書）
- 稅捐稽徵處（土增稅、契稅申報）
- 鄉鎮市公所（契稅申報書）
- 銀行（對保、抵押設定）
- 地政機關（塗銷、過戶）

系統目前缺乏「今天要去哪些機關、帶哪些文件」的跑件規劃功能。

**稅務法定期限（比想像中嚴格）**
- 土地增值稅：**訂約後 30 日內**申報，逾期以收件日當期公告現值計算（可能多繳稅）
- 契稅：**訂約日起 30 日**申報
- 房地合一稅：**過戶後一個月內**繳納（新制）

這三個法定期限目前系統沒有從「簽約日」自動推算並警示。

## 一-B、從多個代書網站學到的真實現場知識

### 流程時間的精確修正

爬取 10+ 個代書事務所與房產網站後，確認以下時間基準（更精確）：

| 階段 | 實際時間 | 系統影響 |
|------|---------|---------|
| 簽約→交屋（有貸款） | **30～45 天** | 倒數計時的重要性更高 |
| 簽約→交屋（無貸款） | **約 10 天** | 需支援「極速案件」模式 |
| 用印後到完稅 | **7～14 天** | 不是月，是週 |
| 稅單核發（一般稅率） | **3～10 工作天** | 這段要追蹤等待 |
| 稅單核發（自用稅率） | **10～25 工作天** | 自用住宅等稅單等最久 |
| 銀行對保到撥款 | **2～3 週** | 銀行等待狀態需清楚標示 |
| 塗銷完成 | **2～3 工作天**（清償後） | 代償後的等待節點 |
| 二撥後交屋 | **確認謄本乾淨才能進行** | 目前系統無此檢查點 |

### 案件類型的真實差異（系統目前只做買賣）

從多個地政士事務所網站整理，代書實際承辦的案型遠不只買賣：

| 案型 | 特殊流程重點 | 目前系統支援 |
|------|------------|------------|
| **買賣移轉** | 四階段流程（現有） | ✅ 完整支援 |
| **繼承登記** | 需先到國稅局查財產→申報遺產稅→地政登記，有 6 個月申辦期限 | ❌ 無 |
| **贈與登記** | 每年免稅額 244 萬，分年贈與需追蹤歷年進度 | ❌ 無 |
| **抵押權設定** | 銀行貸款附帶，費用 4,000～5,000 元/順位 | ❌ 無獨立追蹤 |
| **抵押權塗銷** | 還清貸款後辦，費用 2,000～2,200 元/順位 | ❌ 只有代償日期 |
| **信託登記** | 自益/他益信託流程不同，費用 12,000～15,000 元 | ❌ 無 |
| **法拍屋過戶** | 7 日內繳清價金，產權移轉特殊（無印鑑證明） | ❌ 無 |
| **預售屋讓渡** | 讓渡契約費 5,000 元/人，流程更複雜 | ❌ 無 |

**建議**：在案件建立時增加「案件類型」欄位，不同類型套用不同的里程碑模板。

### 代書收費結構（系統未追蹤，但影響財務核算）

整合冠亨、里衡、禾禮三家事務所的公開費率：

**買賣案（代書費，不含政府規費）**

| 項目 | 費用範圍 |
|------|---------|
| 簽約見證（買方） | 1,500～3,000 元 |
| 簽約見證（賣方） | 1,500～3,000 元 |
| 所有權移轉登記 | 12,000～15,000 元/組 |
| 抵押權設定（買方銀行） | 4,000～5,000 元/順位 |
| 抵押權塗銷（賣方舊貸） | 2,000～2,200 元/順位 |
| 土增稅申報 | 2,000～3,000 元 |
| 房地合一稅申報 | 6,000 元 |

**政府規費（另計，代書代收）**

- 地政規費：移轉申報地價 × 1‰
- 契稅：房屋評定現值 × 6%
- 印花稅：公定契約金額 × 1‰

**系統改進建議**：在 `financials` 加入「代書費用明細」欄位，自動計算預收總額，結案時與實收對帳。

### 印鑑證明的風險管理（系統應加入提醒）

多個網站都強調印鑑證明的安全風險：

> 「印鑑證明落入他人手中，可能被用來辦理貸款或不動產交易」

**系統應有的保護機制**：
- 記錄印鑑證明的「用途記載」（應填「不動產登記」或「不限定用途」）
- 追蹤印鑑證明的申請日期與張數
- 用印完成後提醒確認是否已收回或核銷

### 代書的真實工作壓力（設計依據）

冠亨地政士事務所的文章揭露：

> 「月簽約 40 件才有機會年薪百萬，不管凌晨幾點都要配合，否則失去案源」

這說明系統必須支援：
- **多案件並行管理**（40 件同時進行）
- **隨時隨地存取**（手機端是必需品，不是加分項）
- **最短路徑操作**（凌晨簽完約，回家還要更新系統，步驟不能超過 3 步）

## 二、流程設計改進

### 2.1 「暫停狀態」的細分（目前最大缺口）

**現況**：案件只有 Processing / Closed / Cancelled，缺乏中間態描述。

**問題**：實務中「卡住」的原因千百種，差異巨大：

| 卡住類型 | 需要追蹤的事 | 建議狀態標籤 |
|----------|------------|------------|
| 等待銀行對保 | 哪家銀行、哪位窗口、何時催 | `等待銀行` |
| 等買方補件 | 缺哪份文件、誰要準備 | `等待買方` |
| 等賣方補件 | 缺哪份文件 | `等待賣方` |
| 等地政申報回復 | 案號、送件日、預計出件 | `地政處理中` |
| 等法院塗銷 | 案號 | `法院程序中` |

**建議**：在 `on_hold_reason` 基礎上，增加結構化的阻塞追蹤：

```
案件阻塞資訊：
- 阻塞類型（下拉選單）
- 阻塞描述（自由文字）
- 預計解除日期
- 負責追蹤人
```

---

### 2.2 「代償」流程的獨立追蹤

**現況**：代償僅有一個日期欄位（`redemption_date`）。

**問題**：代償是整個流程中最複雜、最容易出錯的環節。現實步驟：

```
1. 確認原貸款餘額（需到銀行查）
2. 申請代償撥款（買方銀行）
3. 確認撥款日（常與交屋日不同）
4. 原貸款銀行確認收款
5. 申請塗銷抵押設定
6. 等塗銷完成（3～5 工作天）
7. 確認土地建物謄本乾淨
```

**建議**：增加「代償進度追蹤」子模組，每步驟可勾選完成，並記錄各步驟日期。

---

### 2.3 稅務申報的流程導引

**現況**：只追蹤繳納期限，缺乏「申報前置作業」的提醒。

**問題**：土地增值稅申報需要在**過戶前**完成，但系統目前只提醒繳納日期，沒有提醒申報準備。

**建議**：每個稅務期限自動生成兩個節點：

1. **申報準備提醒**（過戶前 7 天）：提示準備文件清單
2. **繳納提醒**（期限前 3 天）：現有邏輯已有

---

### 2.4 建立「案件SOP 清單」機制

**現況**：`ChecklistSection` 是固定的辦事清單，無法因案型不同而客製化。

**問題**：土地案、公寓案、預售屋過戶、繼承過戶，SOP 差異極大。

**建議**：

- 建立「案型範本」（建物買賣、土地買賣、繼承、贈與...）
- 新增案件時選擇案型，自動套用對應 SOP 清單
- 支援代書自訂 SOP 範本庫

## 三、時間控管改進

### 3.1 「倒數計時」取代「日期顯示」

**現況**：里程碑顯示的是絕對日期（2026-04-15）。

**問題**：代書在高壓狀態下，看到日期還要自己換算「還有幾天」，增加認知負擔。

**建議**：UI 同時顯示**日期 + 剩餘天數**：

```
交屋日：2026-04-15 (還有 11 天)    ← 綠色
完稅：  2026-04-06 (還有 2 天)     ← 橘色警示
土增稅：2026-04-03 (已逾期 1 天)   ← 紅色緊急
```

顏色規則：7天+ 綠色、3-7天 橘色、3天內 紅色、逾期 閃爍紅色。

---

### 3.2 「今日工作清單」的智能排序

**現況**：`TodayFocus` 顯示今日相關事項，但無智能排序。

**問題**：代書早上開電腦，面對一堆任務，需要自己判斷優先序，消耗決策能量。

**建議**：今日清單依以下規則自動排序：

1. **逾期任務**（最優先，標紅）
2. **今天截止**（今日必完成）
3. **3天內截止**（提前準備）
4. **銀行/地政窗口相關**（受辦公時間限制，需早上處理）
5. **等待回應**（追蹤類，彈性時間）

---

### 3.3 「批次作業日」的規劃功能

**現況**：系統無法做跨案件的「同日作業規劃」。

**問題**：代書常需在同一天跑地政、跑銀行，可以順便整合多案件的跑單業務，節省時間。

**建議**：增加「今日行程規劃」功能：

- 按地點分組（地政登記所、各銀行）
- 顯示同日需到同一地點辦理的所有案件
- 支援列印「跑單清單」

---

### 3.4 「法定期限計算器」整合

**現況**：稅務計算器是獨立工具，無法直接套用到案件時程。

**問題**：土增稅申報期限（契約成立後 30 日內）、契稅（訂約日起 30 日）等法定期限，每次都要手算。

**建議**：在里程碑設定時，輸入簽約日後，自動推算各項法定期限，並詢問是否套入稅務截止日欄位。

## 四、筆記管理改進

### 4.1 「案件筆記」的結構化升級

**現況**：備忘錄（notes）是純自由文字，私密備註（private_notes）同樣無結構。

**問題**：自由文字看似彈性，實則讓重要資訊淹沒在敘述中。一個月後回頭看，很難快速掌握關鍵事項。

**建議**：將備忘錄改為**結構化筆記板**，分為固定區塊：

```
┌─ 案件摘要（1-2 句自由文字）─────────────────────┐
│                                                    │
├─ 注意事項（條列，可標記重要度）──────────────────┤
│  ⚠️ 賣方有動產設定尚未確認                         │
│  📌 買方要求延後交屋至 5/1，待確認                 │
│                                                    │
├─ 待確認事項（工作項目，可勾選）──────────────────┤
│  ☐ 確認賣方印鑑是否準備                           │
│  ✅ 確認買方貸款核准金額                           │
│                                                    │
└─ 溝通紀錄（時間戳 + 對象 + 內容）────────────────┘
  2026-04-02 仲介李小明：確認交屋日不變
  2026-04-01 買方王大明：詢問尾款流程
```

---

### 4.2 「快速記錄」入口

**現況**：新增筆記需要打開案件詳情頁面，操作步驟較多。

**問題**：代書在電話中接收到重要資訊時，需要在 5 秒內找到記錄入口，否則就會忘記。

**建議**：

- **全局快速輸入**（鍵盤快捷鍵，如 `Ctrl+Shift+N`）：浮動輸入框，選擇案件、輸入內容、儲存
- **儀表板的「今日速記」**：隨時可見的輸入框，記錄後再歸檔到對應案件

---

### 4.3 「溝通紀錄」的結構化

**現況**：與客戶、仲介、銀行的溝通紀錄混雜在備忘錄中。

**問題**：

- 糾紛發生時，無法快速找到「我說過什麼、何時說的」
- 移交案件時，新接手的代書不知道歷史溝通脈絡

**建議**：增加「溝通紀錄」功能：

| 欄位 | 說明 |
|------|------|
| 日期時間 | 自動帶入當下時間 |
| 對象 | 買方 / 賣方 / 仲介 / 銀行（可選已儲存聯絡人） |
| 管道 | 電話 / LINE / 當面 / Email |
| 內容摘要 | 自由文字 |
| 待辦事項 | 此次溝通產生的後續事項 |

---

### 4.4 「知識庫 ↔ 案件」的雙向連結

**現況**：知識庫（/knowledge）是獨立的，無法在案件中引用知識庫文章。

**建議**：

- 在案件筆記中可輸入 `@` 觸發知識庫搜尋
- 被引用的知識庫文章顯示「相關案件數」，方便更新時知道影響範圍
- 案件關閉時，提示「是否將特殊處理方式更新到知識庫」

## 五、UI 設計改進

### 5.1 「案件清單」的資訊密度提升

**現況**：表格式清單，每列顯示的資訊有限。

**問題**：代書掃瞄案件清單時，最需要快速看到的是：「哪些案件今天需要動作」，但目前需要進入個別案件才能看到完整狀態。

**建議**：表格列增加**內嵌狀態指示器**：

```
┌────────────┬──────┬──────────┬─────────────────────────────────┐
│ 案號       │ 地址 │ 現在階段 │ 警示                             │
├────────────┼──────┼──────────┼─────────────────────────────────┤
│ 台北-0412  │ 大安 │ 🟡 完稅  │ ⚠️ 稅務期限 2 天後              │
│ 新北-0380  │ 板橋 │ 🔴 交屋  │ 🔥 今日交屋！尾款確認？         │
│ 台北-0397  │ 中山 │ 🟢 簽約  │ ✅ 無緊急事項                   │
│ 新北-0401  │ 新莊 │ ⏸️ 暫停  │ 💬 等待：銀行對保               │
└────────────┴──────┴──────────┴─────────────────────────────────┘
```

---

### 5.2 「里程碑時間軸」的視覺強化

**現況**：`PipelineStatus` 顯示流程進度，但各階段之間的關係不夠直觀。

**建議**：

1. **甘特圖樣式**：橫軸為時間，每個里程碑顯示計畫日期 vs 實際日期的對比
2. **關鍵路徑標示**：哪個延遲會造成後續連鎖延遲，用紅色路徑標示
3. **法定期限覆蓋**：在時間軸上疊加顯示稅務法定期限

---

### 5.3 「手機端」優先設計

**現況**：UI 以桌面端為主，手機版響應式表現不確定。

**問題**：代書在外跑件時（銀行、地政、客戶家），最常用的操作是：

- 查詢案件資訊（買賣雙方聯絡方式、金額）
- 快速記錄溝通內容
- 確認今天還有哪些事

**建議**：建立**手機端專屬模式**：

- 主頁：今日行程 + 緊急事項（大字體、易點擊）
- 案件詳情：聯絡人電話可直接點撥
- 快速記錄：語音轉文字輸入（整合 Web Speech API）
- 底部 Tab：今日 / 案件 / 速記 / 設定

---

### 5.4 「進場動線」的減少點擊

**現況**：修改案件資訊需要進入詳情頁 → 點擊編輯 → 捲動到對應區段 → 修改 → 儲存。

**問題**：代書電話中確認了新日期，需要在 30 秒內更新，步驟太多容易放棄記錄。

**建議**：

- 案件清單支援**快速編輯**（Hover 顯示編輯按鈕，點擊彈出小 Modal 修改關鍵欄位）
- 里程碑日期支援**行內編輯**（直接點擊日期即可修改，不需進入編輯模式）
- 最常修改的 3 個欄位（下一里程碑日期、備忘、狀態）固定在案件卡片可見位置

---

### 5.5 「大字體模式」與無障礙優化

（根據現有記憶：主使用者為 60 歲長者）

**現況**：已有基本字體提升，label 最低 text-sm。

**建議進一步優化**：

1. **一鍵大字體切換**：在設定中增加「大字體模式」，整體縮放 1.2 倍
2. **高對比模式**：特別針對戶外陽光下查看的場景，提升對比度
3. **觸控目標大小**：所有可點擊元素最小 44×44px（Apple HIG 標準）
4. **關鍵數字加粗**：金額、日期使用 `font-semibold`，比周圍文字更突出
5. **避免純顏色傳遞資訊**：所有警示色搭配圖示，不依賴色覺辨識

## 六、進階功能建議

### 6.1 「委託書管理」模組

代書日常大量處理委託書（授權書），但目前系統無此追蹤。

**建議新增**：
- 委託書類型（一般買賣 / 繼承 / 代理申報）
- 委託人資訊
- 委託範圍
- 有效期限提醒
- PDF 掃描上傳

---

### 6.2 「費用結算」工作流

**現況**：`financials` 表記錄了各項金額，但無費用結算的工作流程。

**建議**：

```
費用結算流程：
1. 預收規費記錄
2. 實際費用明細（地政費、稅費、代書費）
3. 費用結算單自動產生（可列印給客戶確認）
4. 尾款計算（總價 - 已付 - 代償 = 應付尾款）
5. 結算確認（買賣雙方簽認）
```

---

### 6.3 「案件範本」快速建立

**現況**：每個新案件從頭填寫。

**問題**：同一仲介轉介的案件，很多資訊是固定的（城市、常用銀行、仲介聯絡方式）。

**建議**：
- 支援從現有案件複製基本資訊建立新案件
- 建立「客戶範本」（常合作的仲介、建商）
- 新案件建立時自動帶入範本預設值

---

### 6.4 「逾期追蹤」報表

**現況**：個別案件有逾期警示，但無全局統計。

**建議**：每月自動產生：
- 逾期稅務申報統計
- 各案件平均流程時間
- 常見阻塞原因分析
- 與上月比較趨勢

---

### 6.5 「結案總結」功能

**現況**：案件關閉只是狀態改為 Closed，無結案總結機制。

**建議**：結案時觸發結案精靈（Wizard）：

1. 確認所有待辦均已完成
2. 確認費用已結算
3. 填寫結案備註（特殊處理方式、客戶評價）
4. 提示是否歸檔文件
5. 自動產生「結案摘要」供存檔

## 八、結語

Scrivener Flow 已具備完整的技術架構與核心資料模型，是台灣代書業少數真正以工作流程為核心設計的系統。

改進建議的核心邏輯只有一個：**降低代書在壓力下的認知負擔**。

代書在處理多案件時，大腦最脆弱的時刻是：
- 電話中接收到口頭確認
- 同一天要到多個機關跑件
- 一個截止日逼近但另一個案件又突然出狀況

系統的設計應該讓代書在這些時刻，能夠以最少的點擊、最直覺的操作，完成「記錄、確認、推進」的動作。

> 一個好的控案系統，不是讓代書更努力工作，而是讓代書不用記那麼多事。
